# java-sleep-tracker
Техническое задание Sleep Tracker Analyzer
Постановка задачи
Многие люди хотят выработать правильные привычки сна, но реально оценить, во сколько они ложатся, сколько спят и насколько качественно, часто оказывается сложной задачей. В этот раз вам предстоит разработать приложение, которое поможет людям проанализировать записи о своём сне и организовать его более здоровым образом.
Предположим, что у пользователя уже есть специальное устройство — умные часы, которые умеют записывать данные о сне. Они умеют фиксировать моменты засыпания и пробуждения и объединять их в так называемые сессии сна. В большинстве случаев одна сессия сна соответствует одной ночи, хотя бывают исключения: например, если пользователю выдалась возможность поспать днём, часы выявят дополнительную сессию сна. 
Умные часы предоставляют файл с логом сна — набор записей в формате «дата и время засыпания, дата и время пробуждения и качество сна». Качество оценивается часами автоматически на основе количества телодвижений во время сна, а также анализе частоты дыхания и сердцебиения, и может принимать одно из трёх значений: GOOD (хорошее), NORMAL (нормальное), BAD (плохое). Записи в файле упорядочены по дате и времени.
Например, часть файла может выглядеть следующим образом:
01.10.25 22:15;02.10.25 08:00;GOOD
02.10.25 23:00;03.10.25 08:00;NORMAL
03.10.25 14:30;03.10.25 15:20;NORMAL
03.10.25 23:30;04.10.25 06:20;BAD 
Ваша задача — реализовать приложение, которое будет принимать на вход такой файл, анализировать сон пользователя и давать ему в понятном виде информацию о проблемах в его сне и, возможно, некоторые рекомендации для его улучшения.
Приложение будет предоставлять набор аналитических функций для анализа лога сна. Каждая из функций отвечает на определённый вопрос, например, сколько раз за рассматриваемый период пользователь спал недостаточно. При этом мы хотим сделать приложение расширяемым — так, чтобы и нам самим, и другим разработчикам было легко добавлять новые аналитические функции, не изменяя основной код приложения.
Также есть дополнительное условие. Как выяснилось, производители умных часов являются большими фанатами функционального подхода. Они поставили жёсткое условие: ни в одной программе для их часов не должны использоваться традиционные циклы (конструкции вида for, while). Единственное исключение, где это допустимо, — это юнит-тесты. Поэтому вам обязательно нужно учесть это ограничение в своей работе.
Подготовительные работы
Первое, что вам нужно сделать — реализовать каркас приложения для анализа сна. Приложение должно принимать на вход как аргумент командной строки путь к файлу с логом сна, загружать этот файл в память, а затем последовательно запускать все доступные функции анализа.
Создайте класс SleepTrackerApp, это будет основной класс приложения. Добавьте метод main — именно в этом методе будет инициироваться считывание файла и запуск аналитических функций.
Реализуйте чтение файла с логом сна самостоятельно. Подумайте о том, какое представление будет удобно использовать для хранения данных о сессиях сна во время анализа.
Чтобы хранить набор аналитических функций, мы предлагаем создать список со всеми функциями и последовательно выполнять их, передавая на вход каждой прочитанные данные о сессиях сна. При этом код должен отвечать следующим требованиям:
Легко добавлять новые функции.
Каждая функция возвращает одно значение — например, количество сессий сна.
Функции должны запускаться в методе main, а результат их выполнения должен выводиться на экран. Весь код вывода должен располагаться в методе main. При этом пользователю должно быть понятно, что именно посчитала данная функция.
Функции должно быть удобно тестировать.
Подумайте, как организовать представление и хранения функций. Напишите соответствующий код. При необходимости воспользуйтесь нашими подсказками.
И добавьте первую, самую простую аналитическую функцию, — она будет выводить на экран информацию, сколько всего было сессий сна за представленный период. Реализуйте эту функцию самостоятельно и убедитесь, что количество сессий сна считается корректно.
Не забудьте про тестирование. Всегда важно быть уверенным, что код работает корректно. Напишите как минимум два юнит-теста, проверяющих работу новой функции.
Вычисляем базовые метрики
Теперь, когда подход разработан, пришло время наполнить наше приложение реальной функциональностью. Начнём с базовых метрик, которые позволят составить основное представление о своём сне.
Вам нужно разработать функции для вычисления следующих метрик для сна:
минимальная продолжительность сессии (в минутах);
максимальная продолжительность сессии (в минутах);
средняя продолжительность сессии (в минутах);
количество сессий с плохим качеством сна.
Реализуйте каждую из описанных функций. Добавьте эти функции в список используемых аналитических функций. Также напишите не менее двух юнит-тестов для каждой из функций.
Выявляем бессонные ночи
Все знают, что не спать ночами вредно, но иногда ночь может пройти незаметно. Например, за чтением интересной книги или написанием очередного проекта на Java. Чтобы пользователь не упускал из вида такие ночи и всегда точно знал, как часто он допускает бессонную ночь, вам нужно добавить в приложение функцию, которая будет вычислять, сколько раз за всё время логирования сна пользователь не спал ночью.
Временем логирования считаем интервал от начала первой сессии сна в файле до окончания последней. При этом считаем, что пользователь носит часы не снимая — то есть не было сессий сна, которые не попали бы в файл. 
Бессонной ночью считается ночь, когда не было ни одной сессии сна, пересекающей интервал от 0:00 до 6:00. То есть, если пользователь спал с 23:00 до 3:00, ночь не будет считаться бессонной, также как если он спал с 2:00 до 7:00. А вот если сон был только с 7:00 до 11:00, такую ночь мы запишем в бессонные.
Также будем считать, что если первая сессия сна в файле началась после 12 дня, потенциальной ночью для сна считается следующая ночь, а если до 12 — то предыдущая.
Реализуйте функцию, вычисляющую количество бессонных ночей. Добавьте её в общий список функций и не забудьте про юнит-тесты. Эта функция содержит более сложную логику, чем предыдущие. Поэтому вам нужно написать не менее четырёх юнит-тестов. Подумайте, какие будут крайние случаи для этой функции, и обязательно добавьте для них тест.
Классифицируем пользователя
Существует деление людей по хронотипу на «сов» и «жаворонков». «Совы» любят поздно ложиться и поздно вставать, а «жаворонки», наоборот, рано ложатся и рано встают. Также выделяют промежуточный тип «голуби», который характеризуются средним временем отхода ко сну и пробуждения.
Добавьте в приложение возможность определять, к какому хронотипу относится пользователь.
Для этого выполните два шага:
Для каждой ночи на основе времени засыпания и пробуждения определите, относится ночь к типу «сова», «жаворонок» или «голубь».  
«Сова» — если время засыпания было после 23:00, а время пробуждения — после 9:00.
«Жаворонок» — если время засыпания было до 22:00, а время пробуждения до — 7:00.
«Голубь» — во всех остальных случаях.
Бессонные ночи и дневные сессии сна в подсчёте должны игнорироваться.
Посчитайте количество ночей каждого типа и выберите, какой встречается чаще всего. Именно к этому типу нужно отнести пользователя. Если есть сомнения, например, количество ночей двух типов совпадает, считайте, что пользователь относится к «голубям».
Реализуйте представленный алгоритм в отдельной функции. Обратите внимание, что результатом работы новой функции будет не число, а тип пользователя. Подумайте, как это реализовать, чтобы остальные функции и код вывода результата продолжили работать по-прежнему. 
Обязательно протестируйте свой алгоритм с помощью юнит-тестов.
